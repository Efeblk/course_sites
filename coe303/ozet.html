2. Long questions: akışı açıkla, örneği çöz

Uzun soruların konusu format bilgisinde belirtilmiyor. Bunlar Chapters 1–4 içindeki örneklerdir; çıkacak soru tahmini değildir.

Kesmeden dönüşe kadar denetim

  1. Cihaz tamamlanınca interrupt gönderir.
  2. CPU mevcut komutu tamamlar; PC ve registers kaydedilir.
  3. Interrupt vector handler adresini verir.
  4. Handler kernel mode içinde çalışır.
  5. Durum geri yüklenir; program devam eder.

DMA ile blok başına bir tamamlanma kesmesi kullanılır. Dersin interrupt-driven modelinde word başına kesme vardır. Interrupt Lab içinde sırayı adımla.

System call: iki mode değişimi

Program read gibi bir API çağırır. Çağrı numarası ve parametreler hazırlanır. Kontrollü giriş user → kernel geçişini yapar. Numara handler seçer; sonuç dönünce kernel → user geçişi olur.

Parametreler registers, adresi register içinde verilen memory block, veya stack üzerinden iletilir. System-call lab içinde üçünü karşılaştır.

Process durumları ve context switch

New → Ready: kabul. Ready → Running: dispatch. Running → Waiting: I/O bekleme. Waiting → Ready: olay tamamlanması. Running → Ready: zaman dilimi bitişi. Running → Terminated: exit.

P0 I/O beklerken OS durumunu PCB0 içine kaydeder; hazır P1 durumunu PCB1 üzerinden yükler. Geçiş sırasında uygulama işi yapılmaz. P0'ın I/O işlemi bitince Ready olur; hemen Running olmak zorunda değildir.

fork sayısını adım adım bul

  1. Başlangıçta bir process vardır.
  2. Her process ilk başarılı fork çağrısını yürütür: toplam 2.
  3. İkisi de ikinciyi yürütür: toplam 4.
  4. Dördü de üçüncüyü yürütür: toplam 8; yeni çocuk sayısı 7.

2ⁿ kuralı her process her çağrıyı yürüttüğünde geçerlidir. Koşullu kodu görmeden üs alma. exec yeni process eklemez; programı değiştirir.

Bounded buffer: bir slot neden boş?

in sonraki boş yeri, out sonraki okunacak yeri gösterir. in == out boş demektir. Dolu koşulu (in + 1) % SIZE == out. Koşulları ayırmak için bir slot ayrılır.

  1. SIZE = 10: fiziksel slot sayısı.
  2. Kapasite 10 − 1 = 9 items.
  3. Üretici dolu durumda bekler; tüketici bir öğe alınca yer açılır.

Amdahl: serial kısmı ayır

  1. S = 0.25: serial oran. N = 2: çekirdek sayısı.
  2. Parallel oran: 1 − S = 0.75.
  3. Normalize süre: S + (1 − S)/N = 0.25 + 0.375 = 0.625.
  4. Hızlanma: 1/0.625 = 1.6.
  5. N büyüdükçe sınır: 1/S = 4.

Yüzdeyi kesre çevir; yüzde 25 yerine 25 yazma. Amdahl Lab içinde aynı örneği dene.

Thread modellerini bloklanma ile ayır

Many-to-one: birçok user thread tek kernel thread'e bağlı; biri bloklanınca hepsi etkilenir, çok çekirdekte paralellik yoktur. One-to-one: her user thread bir kernel thread'e bağlı; diğerleri çalışabilir. Many-to-many: user thread'ler daha küçük veya eşit sayıdaki kernel thread'e eşlenir.

Pthreads: create işi başlatır, join bitmesini bekler, exit thread'i bitirir. Worker'ın sum değerini okumadan önce join yapılır. Dört yarar: responsiveness, resource sharing, economy, scalability.

Lost update izini takip et

Counter 0 iken A ve B ayrı ayrı 0 yükler. A 1 hesaplayıp yazar. B eski 0 değerinden 1 hesaplayıp yazar. Sonuç 2 yerine 1. Paylaşılan bellek güncellemeleri kendiliğinden atomik yapmaz.
