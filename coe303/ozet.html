2. Long questions: akışı açıkla, örneği çöz

Uzun soruların konusu duyurulmadı. Aşağıdakiler Chapters 1–6 içindeki örneklerdir; son üçü slaytların "midterm question" dediği Chapter 5 ve 6 işleridir.

Kesmeden dönüşe kadar denetim

  1. Cihaz tamamlanınca interrupt gönderir.
  2. CPU mevcut komutu tamamlar; PC ve registers kaydedilir.
  3. Interrupt vector handler adresini verir.
  4. Handler kernel mode içinde çalışır.
  5. Durum geri yüklenir; program devam eder.

DMA ile blok başına bir tamamlanma kesmesi kullanılır. Dersin interrupt-driven modelinde word başına kesme vardır. Interrupt Lab içinde sırayı adımla.

System call: iki mode değişimi

Program read gibi bir API çağırır. Çağrı numarası ve parametreler hazırlanır. Kontrollü giriş user → kernel geçişini yapar. Numara handler seçer; sonuç dönünce kernel → user geçişi olur.

Parametreler registers, adresi register içinde verilen memory block, veya stack üzerinden iletilir. System-call lab içinde üçünü karşılaştır.

Process durumları ve context switch

New → Ready: kabul. Ready → Running: dispatch. Running → Waiting: I/O bekleme. Waiting → Ready: olay tamamlanması. Running → Ready: zaman dilimi bitişi. Running → Terminated: exit.

P0 I/O beklerken OS durumunu PCB0 içine kaydeder; hazır P1 durumunu PCB1 üzerinden yükler. Geçiş sırasında uygulama işi yapılmaz. P0'ın I/O işlemi bitince Ready olur; hemen Running olmak zorunda değildir.

fork sayısını adım adım bul

  1. Başlangıçta bir process vardır.
  2. Her process ilk başarılı fork çağrısını yürütür: toplam 2.
  3. İkisi de ikinciyi yürütür: toplam 4.
  4. Dördü de üçüncüyü yürütür: toplam 8; yeni çocuk sayısı 7.

2ⁿ kuralı her process her çağrıyı yürüttüğünde geçerlidir. Koşullu kodu görmeden üs alma. exec yeni process eklemez; programı değiştirir.

Bounded buffer: bir slot neden boş?

in sonraki boş yeri, out sonraki okunacak yeri gösterir. in == out boş demektir. Dolu koşulu (in + 1) % SIZE == out. Koşulları ayırmak için bir slot ayrılır.

  1. SIZE = 10: fiziksel slot sayısı.
  2. Kapasite 10 − 1 = 9 items.
  3. Üretici dolu durumda bekler; tüketici bir öğe alınca yer açılır.

Amdahl: serial kısmı ayır

  1. S = 0.25: serial oran. N = 2: çekirdek sayısı.
  2. Parallel oran: 1 − S = 0.75.
  3. Normalize süre: S + (1 − S)/N = 0.25 + 0.375 = 0.625.
  4. Hızlanma: 1/0.625 = 1.6.
  5. N büyüdükçe sınır: 1/S = 4.

Yüzdeyi kesre çevir; yüzde 25 yerine 25 yazma. Amdahl Lab içinde aynı örneği dene.

Thread modellerini bloklanma ile ayır

Many-to-one: birçok user thread tek kernel thread'e bağlı; biri bloklanınca hepsi etkilenir, çok çekirdekte paralellik yoktur. One-to-one: her user thread bir kernel thread'e bağlı; diğerleri çalışabilir. Many-to-many: user thread'ler yeterli sayıda (sufficient number) kernel thread'e eşlenir.

Pthreads: create işi başlatır, join bitmesini bekler, exit thread'i bitirir. Worker'ın sum değerini okumadan önce join yapılır. Dört yarar: responsiveness, resource sharing, economy, scalability.

Pthreads kodu: başlat, bekle, sonucu oku

Dersin runner örneğinde worker, 1’den 5’e kadar toplayıp global sum’a yazar. Bütün çağrılar başarılı ve başlangıç sum = 0 olsun:

pthread_t tid;
char limit[] = "5";
pthread_create(&tid, NULL,
               runner, limit);
pthread_join(tid, NULL);
printf("%d\n", sum);
  1. Create: runner’da bir worker başlatır; limit argümanıdır.
  2. Worker 1 + 2 + 3 + 4 + 5 = 15 hesaplar.
  3. Join: worker bitmeden geri dönmez; main sonra 15’i yazdırır.

Lost update izini takip et

Counter 0 iken A ve B ayrı ayrı 0 yükler. A 1 hesaplayıp yazar. B eski 0 değerinden 1 hesaplayıp yazar. Sonuç 2 yerine 1. Paylaşılan bellek güncellemeleri kendiliğinden atomik yapmaz.

Gantt chart: ortalama bekleme süresini adım adım bul

  1. Algoritmaya göre sırayı bul ve Gantt chart çiz. Her çubuğun altına başlangıç ve bitiş zamanını yaz.
  2. Her process için completion time: son çubuğunun bittiği an.
  3. Turnaround = completion − arrival.
  4. Waiting = turnaround − burst: hazır kuyruğunda geçen süre.
  5. Average waiting = toplam / n.

Örnek (slide 19, SRTF): P1 0/8, P2 1/4, P3 2/9, P4 3/5 (arrival/burst). Zaman 1'de P2 gelir; 4 < P1'in kalan 7'si, P1 kesilir. Chart: P1 0–1, P2 1–5, P4 5–10, P1 10–17, P3 17–26. Bekleme: P1 = 17 − 0 − 8 = 9, P2 = 0, P3 = 26 − 2 − 9 = 15, P4 = 10 − 3 − 5 = 2. Ortalama 26 / 4 = 6.5.

Race condition: count = 5 nasıl 4 olur?

Producer count++, consumer count-- çalıştırır. Her biri üç makine adımıdır.

  1. T0 producer: register1 = count (5)
  2. T1 producer: register1 = register1 + 1 (6)
  3. T2 consumer: register2 = count (5, eski değer)
  4. T3 consumer: register2 = register2 − 1 (4)
  5. T4 producer: count = register1 (6)
  6. T5 consumer: count = register2 (4)

Doğrusu 5. T4 ile T5 yer değiştirse 6 olur. Count'a dokunan üç satır critical section'dır. Üç şart: mutual exclusion, progress, bounded waiting. Critical Section Lab içinde sırayı sen seç.

Kâğıda kod: Peterson, mutex, semaphore

Peterson (Pi, j = 1 − i): flag[i] = true; turn = j; while (flag[j] && turn == j) ; /* critical section */ flag[i] = false. turn'ü en son yazan bekler. Kâğıt üzerinde üç şartı sağlar; modern CPU'da reordering yüzünden memory barrier gerekir.

Mutex: pthread_mutex_lock(&m); counter++; pthread_mutex_unlock(&m); Derleme: gcc -pthread. Üç hata: iki kilidi ters sırada almak (deadlock), unlock'u unutmak, aynı mutex'i iki kez kilitlemek.

Semaphore (slide 29, kuyruklu sürüm): wait(S): S--, S < 0 ise blok. signal(S): S++, bekleyen varsa birini uyandır. Mutual exclusion: mutex = 1. Sıralama: synch = 0; P1: S1; signal(synch). P2: wait(synch); S2. Pthreads: sem_init(&s, 0, 1), sem_wait, sem_post. Slaytlarda iki sürüm var: slide 27 busy waiting ile yazar (while (S <= 0) ; S--), orada S hiç negatif olmaz. Slide 27 binary semaphore'a "mutex ile aynı" der; slide 31 ve 45 farkı ekler: ownership.

Deadlock: P0: wait(S); wait(Q). P1: wait(Q); wait(S). Biri S'yi, diğeri Q'yu tutar; ikisi de bekler. Çözüm: aynı sırayla al. Condition variable: mutex'i kilitle; while (!ready) pthread_cond_wait(&c, &m); (spurious wakeup yüzünden while).
