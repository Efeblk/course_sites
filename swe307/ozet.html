Nasıl yazılır: önce iki kavramı birer cümleyle tanımla, sonra farkı ya da artı/eksiyi madde madde yaz, sonda slayttaki kilit cümleyi ekle. Paragraf ezberleme; anahtar kelimeler yeter.

Systems Analyst sorulmuş · Ch1 s30–31

İşletmenin ihtiyacı ile teknik ekip arasındaki köprü.

  • studies problems (düzeltilmesi gereken durum), opportunities (şikâyet yokken iyileştirme), directives (yasal/zorunlu değişiklik) and needs
  • decides how people, data, processes and IT can improve the business
  • must understand the organizational model: who is responsible for which process/decision, what information is required by whom
  • must know techniques and tools to plan, design, implement; works in a team

Functional vs Nonfunctional sorulmuş · Ch5 s10–25

  • Functional = sistemin ne yaptığı: activities and services, how the product must behave. e.g. "The student shall display his/her weekly schedule."
  • Nonfunctional = ne kadar iyi / hangi sınırlar içinde: quality attributes, constraints, interfaces, error handling. e.g. performance "≤ 6 s response for 5,000 users/hour", security "password ≥ 8 chars, 1 upper case, 1 digit", availability "98% of business hours", reliability "≤ 2 level-one faults per month", portability "Windows and Linux".

Henüz sorulmamış ama aynı tarzda gelebilir

  • SDLC phases + outputs: Planning → SPMP; Analysis → SRS; Design → SDD; Development → code; Testing → tested system; Deployment → delivered system, trained users; Maintenance → fixes, enhancements.
  • Testing levels: unit (one module) → integration (modules together) → regression (change broke nothing) → system (whole vs user requirements) → beta (users, real world) → acceptance (project owner, release decision).
  • XP vs Scrum: XP = weekly cycles, TDD, pair programming (driver + navigator), continuous integration, 40-hour week. Scrum = backlog of user stories, 30-day sprint, daily scrum ≤ 15 min by the scrum master, 6–9 people, demo at the end.
  • Include vs Extend: include = always called, dotted arrow from base to included use case. Extend = optional, conditional; base must make sense on its own (Calculate Bonus: deposits over 10,000 or age over 55).
  • Fact-finding: observation (reliable, people act differently), questionnaire (cheap, many people, low return rate), interview (probe and reword, time-consuming), prototyping, sampling, research, JRP.

Tanımlar (soru gelirse): EI data crosses the boundary from outside to inside · EO derived data goes out (report) · EQ retrieves data · ILF data group inside the application · EIF another application's data, reference only. Ranking: EI, EO, EQ use FTR (files referenced) + DET (fields); ILF, EIF use RET (record element types) + DET.

Yedek hesaplar (şimdiye kadar sorulmadı): critical path: TE ileri (birleşmede büyüğü al), TL geri (ayrılmada küçüğü al), slack = TL − TE, slack 0 olanlar kritik. Channels = N(N−1)/2.

4. Fishbone (Ishikawa)

20 puan · 10 teori + 10 senaryo · Ch5 s26–30
  • Purpose: a cause-and-effect tool for a quality problem; shows all possible causes visually to find the root cause. In SAD it is the problem discovery tool of requirements analysis.
  • How to draw: 1) head on the right with the problem (effect) · 2) backbone to the left · 3) branches for 4–8 main causes · 4) attach sub-causes, found by brainstorming.
  • Parts: head = effect · spine = backbone · main bones = cause categories · small bones = sub-causes.

Senaryoya uygularken ana kemikleri sorunun kendisi söylüyor: IS'in 5 bileşeni (Ch1 s17) ve SAD etkinlikleri (Ch2):

Main causeAlt neden fikirleri (örnek; senaryoya göre kendin de yazabilirsin)
Hardwareserver capacity too small for peak load; no backup / load balancing
Softwareno error-handling requirement met (crashes); memory leaks, unhandled errors
Dataunindexed large tables; data entry / conversion errors at deployment
Peopleusers not trained; inexperienced team
Processrushed go-live without beta testing; no post-deployment review
Requirementsno measurable performance NFR; no reliability / availability NFR
Designarchitecture not designed for peak workload; weak database design
Testingno system testing under real load; no regression testing

Effect'i senaryodan aynen yaz (2025 vizesindeki örnek: "PSRAS: high instability and unreliable performance"). 4–8 ana kemik, her birinde en az 2 somut alt neden. Tam çözüm: Geçmiş vizeler, soru 4b.
