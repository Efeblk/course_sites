Week 1 — NLP fundamentals: metni neden sayıya çeviriyoruz?

Bilgisayar sadece sayılarla hesap yapar. Bu yüzden her NLP yöntemi önce metni sayıya çevirir; yöntemler neyi koruduğu ve neyi kaybettiği ile ayrılır. Tarih: kurallar (ELIZA, 1966) → istatistik (n-gram, HMM) → derin öğrenme (Word2Vec, LSTM) → Transformer/LLM (BERT, GPT) → bugün: doğru aracı seçmek.

Model ailesi: BERT = encoder-only (anlama: sınıflandırma, NER, QA). GPT = decoder-only (üretim). T5/BART = encoder-decoder (çeviri, özet).

LLM ne zaman yanlış araç? "Don't use a bulldozer to crack a chestnut." Spam örneği: LLM ≈ $30.000/ay, 100–1000 ms; Naive Bayes < $10/ay, < 10 ms; doğruluk 99.2% vs 98.5%. Ayrıca açıklanabilirlik, gizlilik (veri dışarı gider), az etiketli veriyle özelleştirme, halüsinasyon. Karar: önce ucuz baseline, LLM'i sadece gerekirse.

Week 2 — Text classification: f(text) → label

Bir dokümana önceden tanımlı bir etiket: sentiment, spam/ham, topic, intent… Pipeline: Data → Features → Model → Prediction → Evaluation → veriye geri dön. Klasik yöntemler önce: hızlı, yorumlanabilir, az veriyle çalışır, güçlü baseline.

Week 3 — Counts'tan BERT'e (study deck, 110 slayt)

Klasik kısım: aynı özellikler, üç öğrenme mekanizması

Oyuncak corpus: d1 "good good movie" (+), d2 "good movie" (+), d3 "bad bad movie" (−), d4 "bad movie" (−). 4 doküman, 3 kelime tipi, 10 token, her sınıfta 5 token.

  • TF-IDF: idf = ln(N/df): good ln 2, bad ln 2, movie ln 1 = 0. d1 good = 2 × ln 2 ≈ 1.386. "good" 10 kez geçse df hâlâ 2. scikit-learn varsayılanı farklı: ln((1+N)/(1+df)) + 1 ve L2 normalizasyon; bu yüzden kütüphane sayıları farklı çıkar.
  • Leakage: vectorizer'ı (sözlük + IDF) sadece train üzerinde fit et; valid/test için transform. Test'te fit_transform = sızıntı. Bilinmeyen kelimenin sütunu yok; tamamen bilinmeyen doküman sıfır vektör olur.
  • Naive Bayes: prior = doküman sayısı (2/4), likelihood = token sayısı. Add-one: (count + 1)/(5 + 3) → good|+ = 4/8 = .5, bad|+ = 1/8, movie = 3/8. Log uzayında: score(c) = ln P(c) + Σ n ln P(t|c); "good movie" → + : −2.367 vs − : −3.753, pozitif kazanır. Posterior .09375/.1171875 = 0.8 (model olasılığı, doğruluk değil).
  • Logistic regression: z = w·x + b = 0.8×2 − 0.4 = 1.2, p = σ(1.2) ≈ .769. Odds = eᶻ, z = log-odds. Loss = −[y ln p + (1−y) ln(1−p)]. Gradyan (p − y)x, bias gradyanı p − y. Güncelleme w ← w − η g (0.8 → 0.846). x = 0 olsa bile bias öğrenir.
  • SVM: f = good − bad, m = y f(x). Hinge = max(0, 1 − m): m ≥ 1 → 0; 0 < m < 1 doğru ama ceza; m < 0 yanlış. Amaç ½||w||² + C Σ Lᵢ; büyük C ihlali daha çok cezalar. Uzaklık = |f|/||w||; margin genişliği 2/||w||.
  • Negation: unigram "not good"u pozitif okuyabilir (z = +0.4). Bigram "not good" −1.2 ağırlıkla z = −0.8 → negatif. Sınıflandırıcıyı değiştirmek eksik özelliği düzeltmez.

Değerlendirme

TP 30, FN 10, FP 5, TN 55 → P = 30/35 ≈ .857, R = 30/40 = .75, F1 = 2TP/(2TP+FP+FN) = 60/75 = 0.8 (harmonik ortalama, aritmetik değil). Negatif sınıf F1 = .88 → macro-F1 = .84, support-ağırlıklı .848, accuracy .85, hep-negatif baseline .60. Train → fit, validation → seç, test → bir kez. Eşik ağırlığı değil kararı değiştirir.

Week 4 — POS & NER (Jurafsky & Martin; 6. haftanın kaynağı)

  • POS tagging: x₁…xₙ → y₁…yₙ, kelime başına bir etiket; bir belirsizlik giderme işi. "Book that flight" VERB, "that book" NOUN. "back": ADJ, NOUN, VERB, PART, ADV.
  • Open class (NOUN, VERB, ADJ, ADV, INTJ) yeni üye alır; closed class (DET, PRON, ADP, CCONJ, AUX, PART) sabit. UD tagset 17 etiket.
  • Kelime tiplerinin ~%15'i belirsiz ama bunlar sık kelimeler, bu yüzden token'ların ~%60'ı belirsiz. Most-frequent-tag baseline ~%92 (bilinmeyen → NOUN), iyi tagger'lar ~%97. (6. hafta hocası: %97'yi koşulsuz genel gerçek gibi tekrarlama.)
  • Bilgi kaynakları: kelimenin önceliği ("will" genelde AUX), komşu kelimeler, morfoloji/şekil (-ly, un-, büyük harf).
  • NER: PER, ORG, LOC, GPE (+ tarih, para). POS'tan zor: segmentasyon (sınırlar) ve tip belirsizliği (Washington). Şemalar: IO n+1, BIO 2n+1, BIOES 4n+1. IO iki komşu aynı tip varlığı ayıramaz.

Açık uçlu cevap kalıbı (yarım sayfa)

Hoca: "give your verdict, then justify it with the underlying mechanism". İngilizce şu sırayla yaz:

  1. Verdict (1 cümle): "I would choose X / The answer is Y, because …"
  2. Mechanism (2–3 cümle): X neye bakar, ne girer, ne çıkar, formülün anlamı.
  3. Why not the alternative (1–2 cümle): önceki yöntem neyi çözemiyordu.
  4. Limit (1 cümle): X nerede hâlâ başarısız, nasıl test edersin (held-out split, per-class F1, baseline).
Olası sorular: HMM vs CRF (NER için); Naive Bayes vs logistic regression vs SVM; BoW → embedding → RNN/LSTM → Transformer gelişimi; neden accuracy yerine span F1; spam için LLM mi klasik model mi; uzun metinde BERT truncation; padding ve mask neden gerekli; leakage nasıl önlenir.
