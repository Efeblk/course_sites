W1 · open-ended candidateLLM ne zaman yanlış araç?

Hocanın örneği: spam filtresi. LLM ≈ $30.000/ay, 100–1000 ms, %99.2; Naive Bayes < $10/ay, < 10 ms, %98.5. "Don't use a bulldozer to crack a chestnut."

Write this For a simple, high-volume task like spam filtering I would not choose an LLM. A classical model such as Naive Bayes on bag-of-words features reaches almost the same accuracy (98.5% vs 99.2% in the lecture example) at a tiny fraction of the cost (under $10 vs about $30,000 per month) and latency (under 10 ms vs 100–1000 ms). It is also more interpretable, keeps the data private (nothing is sent to an external API), and does not hallucinate. I would start with a cheap baseline and move to an LLM only if the baseline fails on held-out data.

Week 2 — Text classification

W2 · open-ended candidateNaive Bayes vs logistic regression vs SVM

Üçü de aynı özelliklerle (BoW, TF-IDF) çalışır; fark nasıl karar verdikleri. NB generative (sınıfın kelimeleri üretme olasılığı), LR ve SVM discriminative (doğrudan sınır öğrenir).

Write this Naive Bayes is generative: it picks the class with the largest P(c) × ∏ P(word|c). It is fast, works with little data and is a strong baseline, but it assumes words are independent given the class, so correlated words are counted twice, and it needs smoothing because an unseen word would make the product zero.
Logistic regression is discriminative: it learns weights and outputs p = σ(w·x + b), a probability of the positive class (threshold 0.5). Despite the name it is a classifier, and its decision boundary is linear.
SVM finds the maximum-margin hyperplane; the sign of f(x) = w·x + b gives the class. The score is not a probability; kernels allow non-linear boundaries, but it is slower on large data.
Recommended order for a project: Naive Bayes baseline → logistic regression → SVM if time allows.
Traps
  • "Logistic regression is a regression model for continuous outputs"
  • "An SVM score is a probability"
  • "Naive Bayes is discriminative"

W3Leakage: fit on train only

"May we call fit_transform on the test set because it has no labels?" Answer: "no; that would learn a new representation from test data and also potentially change column meanings. Use transform with the fitted representation."
Write this The vectorizer (vocabulary and IDF values) must be fitted on the training set only; validation and test data are only transformed with it. Calling fit_transform on the test set leaks test information into the representation and can change the meaning of the columns. Validation data is used to choose settings; the test set is used once, for the final evaluation. Reusing test results for tuning makes the final test unfair. Duplicates or chunks of the same document must stay in the same split.

W3 · calcNaive Bayes ("good movie")

Calculate prior: P(+) = P(−) = 2/4 = 0.5 (doküman sayısı)
add-one: P(t|c) = (count + 1) / (5 + 3)
+: good 4/8, bad 1/8, movie 3/8  |  −: good 1/8, bad 4/8, movie 3/8
score(+) = 0.5 × 4/8 × 3/8 = 0.09375
score(−) = 0.5 × 1/8 × 3/8 = 0.0234375 → positive wins
posterior P(+|x) = 0.09375 / (0.09375 + 0.0234375) = 0.8
log space: ln P(c) + Σ n·ln P(t|c) → + : −2.367, − : −3.753 (daha az negatif kazanır)

W3 · calcLogistic regression

"What happens to the score when another good token is added?" Answer: "it increases by .8, so the positive probability rises."
Calculate features [good, bad], x = [2, 0]; w = [0.8, −1]; b = −0.4
z = 0.8×2 + (−1)×0 − 0.4 = 1.2
p = σ(1.2) = 1 / (1 + e−1.2) ≈ 0.769 → positive (p ≥ 0.5 ⇔ z ≥ 0)
z = log-odds = ln(p / (1−p)); loss = −[y ln p + (1−y) ln(1−p)]
gradient: ∂L/∂w = (p − y)x, ∂L/∂b = p − y; update w ← w − η·g

W3 · calcSVM hinge loss

Calculate m = y·f(x), hinge = max(0, 1 − m)
m ≥ 1 → loss 0 (doğru ve güvenli)  |  0 < m < 1 → doğru ama ceza (f = 0.5, y = +1 → loss 0.5)  |  m < 0 → yanlış
objective ½‖w‖² + C·ΣLᵢ (büyük C ihlali daha çok cezalar); margin width = 2/‖w‖

W3Static embeddings, Word2Vec, FastText

"If movie appears twice in a sentence, which row does a static embedding lookup retrieve?" Answer: "the same row both times."
  • Embedding table: ID → E[ID] satırı. ID'nin sayısal sırası anlam taşımaz. Lookup kelimeleri birleştirmez; encoder veya pooling lazım. Boyutlar: (B, L) → (B, L, d).
  • CBOW: bağlamdan merkezi tahmin eder ([love, movie] → this). Skip-gram: merkezden bağlamı tahmin eder (this → love, this → movie). Etiket gerekmez, cümle hedefi kendisi verir.
  • GloVe: corpus genelindeki co-occurrence sayılarına uyar. FastText: karakter n-gram'ları; <evler> 7 karakter, pencere 3 → 7 − 3 + 1 = 5 parça → nadir ve çekimli kelimeler (Türkçe) için iyi.
  • Static: "river bank" ve "bank loan" aynı vektör. Contextual encoder her geçişe farklı vektör verir.

W3 · open-ended candidateBoW → RNN → LSTM → Transformer: her adım neyi düzeltti?

Write this Bag of words / mean pooling loses word order. A CNN learns local n-gram-like windows (L − k + 1 windows), but pooling discards position and narrow windows miss distant relations. An RNN reads tokens in order, ht = tanh(Wxxt + Whht−1 + b), but gradients multiplied over many steps vanish (0.520 ≈ 10−6) or explode (1.520 ≈ 3325); clipping only controls exploding. An LSTM adds gates and a cell state, c = f·cold + i·g, h = o·tanh(c), so information can be kept over longer distances, but it is still sequential and not parallel. A BiLSTM also reads right context (2H features) but cannot stream. The Transformer lets every token attend directly to every other token in parallel with softmax(QKT/√dk)V; its cost grows with T² and the input length is fixed, so long texts are truncated. BERT is a pretrained bidirectional Transformer encoder, fine-tuned with a task head.

Week 4 — POS & NER

W4POS tagging belirsizliği

  • Kelime tiplerinin (types) ~%15'i belirsiz, ama bunlar sık kelimeler → token'ların ~%60'ı belirsiz. Örnek "book book book cat dog": belirsiz tip 1/3, belirsiz token 3/5.
  • "Book that flight" → VERB, "hand me that book" → NOUN. "back" 5 farklı POS alabilir.
  • Most-frequent-tag baseline ~%92 (bilinmeyen → NOUN). book: NOUN 6, VERB 4 → her zaman NOUN → "Book a flight"ı yanlış etiketler.
  • Open class (NOUN, VERB, ADJ, ADV) yeni üye alır; closed class (DET, PRON, ADP, AUX…) sabit.

W4NER neden POS'tan zor? Etiket şemaları

Write this NER is harder than POS tagging because it needs both segmentation (finding where a multi-word entity starts and ends, e.g. "San Francisco") and type disambiguation (Washington can be a person, a location or an organization). It is represented with token labels but evaluated on recovered spans. For n entity types, IO uses n+1 labels, BIO 2n+1 and BIOES 4n+1; IO cannot separate two adjacent entities of the same type.

n = 3 → IO 4, BIO 7, BIOES 13. NER bir mention'ı bulur; onu bir veritabanı kimliğine bağlamak (entity linking) ayrı bir görev. Flat BIO, iç içe (nested) varlıkları gösteremez.

W6 · calc · most likelyHMM: "can fish" (joint, posterior, Viterbi, forward)

"Does b(y,x) mean the probability of y given x?" Answer: "no; it means P(x|y)." — "Is 0.1344 a joint path weight or a posterior? Joint; divide by 0.2448 to get the posterior."

Parametreler: start π(N) = 0.6, π(V) = 0.4. Transition N→N 0.3, N→V 0.7, V→N 0.8, V→V 0.2. Emission P(can|N) 0.4, P(fish|N) 0.6, P(can|V) 0.7, P(fish|V) 0.3.

Calculate P(X,Y) = π(y₁) · b(y₁,x₁) · a(y₁,y₂) · b(y₂,x₂)
first position: N 0.6×0.4 = 0.24, V 0.4×0.7 = 0.28
NN = 0.24×0.3×0.6 = 0.0432
NV = 0.24×0.7×0.3 = 0.0504
VN = 0.28×0.8×0.6 = 0.1344 ← best path (joint)
VV = 0.28×0.2×0.3 = 0.0168
P(X) = sum = 0.2448 (forward = sum) → posterior P(VN|X) = 0.1344/0.2448 ≈ 0.549
Viterbi fish/N = max(0.24×0.3, 0.28×0.8) × 0.6 = 0.1344 (from V); Viterbi = max
training = count and normalize: N→N 3, N→V 7 → 0.3, 0.7
Write this (limitations) An HMM is generative: it models the joint P(X,Y) with two local assumptions: each tag depends only on the previous tag, P(yt|yt−1), and each word depends only on its own tag, P(xt|yt). Because the emission sees only one word given one tag, it is hard to add rich, overlapping clues such as capitalization, suffixes, gazetteers or neighbouring words. Unseen events get zero probability and can zero a whole path, so smoothing (and an UNK token) is needed.

  • "b(N, can) is P(N | can)" (P(can | N))

W6 · calc · most likelyLinear-chain CRF: path score, Z, probability, loss

"Which operation selects the best path? Max. Which combines alternatives for Z? Sum." — "Ask if a transition score of 2 is invalid. Answer: no; a score can be any real number."

Unary skorlar: can: N = ln 2, V = 0; fish: N = 0, V = ln 2. Transition V→N = ln 8, diğerleri 0.

Calculate S(Y) = Σ unary + Σ transition; weight = exp(S)
NN = exp(ln 2 + 0) = 2
NV = exp(ln 2 + ln 2) = 4 ← unary tek başına bunu seçer
VN = exp(0 + 0 + ln 8) = 8 ← transition eklenince kazanır
VV = exp(0 + ln 2) = 2
Z = 2 + 4 + 8 + 2 = 16 → P(VN|X) = 8/16 = 0.5
loss(gold VN) = ln Z − S(gold) = ln 16 − ln 8 = ln 2 ≈ 0.693
gradient for θ(V→N) = expected count − gold count = 0.5 − 1 = −0.5 → θ artar
Write this (why CRF over HMM) A linear-chain CRF is discriminative: it models P(Y|X) = exp(S(Y))/Z directly, where S adds unary scores and label-transition scores and Z sums over all label sequences. Unlike an HMM, its unary scores can use rich, overlapping features of the whole input (capitalization, suffixes, name lists, or a neural encoder), and its transition scores still model the compatibility of neighbouring labels. Viterbi uses max to find the best path; Z (a sum) is only needed for probabilities and the training loss.
Traps
  • "A transition score of 2 is invalid because it is above 1" (skor, olasılık değil)
  • "P(VN) = 0.5 means the model is 50% accurate"
  • "Z must be computed to choose the best path"
  • "Training compares the gold path only with the second-best path" (Z bütün yolları içerir)
  • "Training a CRF guarantees legal IOB2" (sonlu skorlar sadece caydırır; yasaklamak için −∞ mask gerekir)

Açık uçlu sorular: cevap kalıbı ve hazır cevap

Hoca: "verdict, then mechanism". Slayt 93: "input, assumptions, operation, result, and what the result means". Yarım sayfa, İngilizce, şu sırayla:

  1. Verdict (1 sentence): "I would choose X, because …"
  2. Mechanism (2–3 sentences): what X looks at, input → output, what the formula means.
  3. Why not the alternative (1–2 sentences): what the previous method could not solve.
  4. Limit and check (1 sentence): where X still fails; how you would test it (held-out split, span F1, baseline).
Example: "HMM or CRF for named entity recognition?" I would choose a linear-chain CRF, because NER needs both rich evidence about each word and consistent neighbouring labels. A CRF models P(Y|X) = exp(S)/Z directly; its unary scores can use overlapping features of the whole sentence (capitalization, suffixes, name lists, or contextual encoder outputs), and its transition scores reward compatible label pairs such as B-PER → I-PER. An HMM also models label transitions, but it is generative: its emission P(word|tag) sees only the current word, so adding overlapping clues is awkward, and unseen words need smoothing. However, a CRF with finite learned scores does not guarantee legal BIO sequences; I would add hard −∞ constraints for illegal transitions and evaluate with exact-match span F1 on a held-out test set, not token accuracy.

Diğer olası sorular (model cevapları deneme vizede): Naive Bayes vs logistic regression vs SVM · BoW → embedding → RNN/LSTM → Transformer · neden accuracy yerine span F1 · spam için LLM mi klasik model mi · uzun metinde BERT truncation · padding ve mask neden gerekli · leakage nasıl önlenir.
