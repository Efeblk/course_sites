Soru 1 · Text classification

A small online shop wants to flag reviews automatically. Training data:

doctextlabel
d1great great item+
d2great item+
d3bad bad item−
d4bad item−
  1. Using multinomial Naive Bayes with add-one smoothing, classify the new review "great great item" and give P(+ | review).
  2. The shop runs the model on 200 new reviews. With negative as the target class: TP = 40, FN = 10, FP = 20, TN = 130. Compute precision, recall, F1 and accuracy, and compare with a model that never flags anything.
  3. The manager wants to replace the model with a large LLM API because it reached 0.88 accuracy in a demo. Give your verdict and justify it.
Çözüm

(a) Naive Bayes

  1. + : great 3, item 2 → 5 tokens
    − : bad 3, item 2 → 5 tokens
    |V| = 3  ·  P(+) = P(−) = 24 = 0.5    Önce sınıf sınıf say. Prior doküman sayar (2/4), likelihood token sayar.
  2. P(great | +) = 3 + 15 + 3 = 12   P(item | +) = 2 + 18 = 38Payda: sınıftaki token + |V|. Her kelimeye 1 ekle.
  3. P(great | −) = 0 + 18 = 18   P(item | −) = 38"great" negatifte hiç yok. Smoothing olmasa 0 olurdu ve bütün çarpım sıfırlanırdı.
  4. s(+) = 0.5 × 12 × 12 × 38 = 364"great" iki kere geçiyor → iki kere çarp. En sık yapılan hata bu.
  5. s(−) = 0.5 × 18 × 18 × 38 = 31024Kısa yol: "item" ikisinde de 3/8, sonucu değiştirmez.
  6. s(+) / s(−) = 16  →  P(+ | d) = 1616 + 1 = 1617 ≈ 0.94 → positiveHesap makinesi yok: 3/64 ile 3/1024'ü bölmek yerine oranına bak. 16'ya 1 → 16/17.
model bu yorumun pozitif olduğuna %94 inanıyor. Bu bir olasılık, accuracy değil.

(b) Precision, recall, F1

  1. P = TPTP + FP = 4060 = 23 ≈ 0.67"Negatif" diye işaretlediklerimin 3'te 1'i yanlış alarm.
  2. R = TPTP + FN = 4050 = 0.8Gerçek negatif yorumların %80'ini yakaladım.
  3. F1 = 2·TP2·TP + FP + FN = 80110 = 811 ≈ 0.73Sayım formu daha kolay: P ve R'yi kesirle uğraşmadan birleştirir. TN yok.
  4. Acc = 40 + 130200 = 0.85Bütün doğru kararlar / hepsi.
  5. Never flag: Acc = 150200 = 0.75,  R = 0,  F1 = 0Baseline: 50 negatif var, kalan 150'yi "doğru" bilir. Accuracy farkı küçük görünür ama baseline hiçbir şey bulmaz.
accuracy 0.85 vs 0.75 küçük bir fark gibi duruyor, ama model kötü yorumların %80'ini buluyor, baseline hiçbirini. Bu yüzden sınıf dengesizken F1'e bakılır.

(c) Karar: LLM mi?

Kâğıda böyle yazarım

Verdict: I would keep the Naive Bayes model (or try logistic regression with bigrams) and not switch to an LLM API.

Why: 0.88 vs 0.85 is a small gain, and a demo is not a held-out test set, so the two numbers are not even comparable. Accuracy is also the wrong metric here: we care about F1 for the negative class. An LLM call for every review costs much more, is slower and sends customer data to an outside service, while NB is cheap, fast and its word likelihoods are easy to inspect.

Limit: NB uses bag of words, so "not great" still counts "great" as positive evidence. I would add bigrams such as "not great", then compare both models on the same test set using negative-class F1.

Karar paragrafında kendi hesabından bir sayı kullan (0.85, 0.75, F1 0.73). "Hesapla, sonra yorumla" istediği şey bu.

Soru 2 · Token classification (NER)

A news agency wants to extract PER, ORG and LOC names. One test sentence:

  1. Compute token accuracy, and exact-match span precision, recall and F1.
  2. Which number should the agency report, and why?
  3. A second model (BERT + softmax head) sometimes outputs O I-PER. Explain why, and what you would change. Would you put an HMM or a CRF on top?
Çözüm

(a) İki ölçü

  1. token acc = 79 ≈ 0.78Token token karşılaştır: sadece "Cook" (I-PER → O) ve "Apple" (B-ORG → B-LOC) yanlış.
  2. gold spans: Ada Lovelace (PER), Tim Cook (PER), Apple (ORG), Cupertino (LOC) → 4BIO'yu isimlere çevir: B ile başlar, I ile devam eder.
  3. predicted: Ada Lovelace (PER) ✓, Tim (PER) ✗, Apple (LOC) ✗, Cupertino (LOC) ✓ → 4"Tim" = sınır yanlış. "Apple LOC" = tür yanlış. İkisi de tam eşleşme değil.
  4. TP = 2,  FP = 4 − 2 = 2,  FN = 4 − 2 = 2Yanlış bir span hem FP (fazla tahmin) hem FN (kaçırılan gold) olur.
  5. P = 24,  R = 24,  F1 = 2·22·2 + 2 + 2 = 0.5Token'da %78, isim düzeyinde %50.
aynı tahmin token bazında 0.78, isim bazında 0.5. Fark O token'lardan geliyor: O'yu bilmek kolay, ama kullanıcı isim istiyor.

(b) ve (c)

Kâğıda böyle yazarım

(b) The agency should report exact-match span F1 (0.5), not token accuracy (0.78). Users need whole names: "Tim" instead of "Tim Cook" is useless, but token accuracy still gives it credit for "Tim". Most tokens are O and easy to get right, so token accuracy looks good even for a weak tagger; in real news text, where about 90% of tokens are O, tagging everything O would score about 90%.

(c) A softmax head takes the argmax at each position independently. It sees the whole sentence through BERT, but it never scores a label pair, so nothing stops O → I-PER. I would add a linear-chain CRF on top: BERT's outputs become the unary scores, the CRF adds transition scores between neighbouring labels, and Viterbi picks the best whole sequence. Training makes O → I-PER unlikely, but finite scores do not forbid it, so I would set that transition to −∞.

Not an HMM: its emission P(word | tag) only looks at the current word, so it cannot use BERT's features or overlapping clues such as capital letters. I would check the fix with span F1 on a held-out test set.

"Neden" sorusunda mekanizmayı söyle: "softmax her konumda ayrı karar veriyor". "Model kötü" demek puan getirmez.

Soru 3 · HMM

A voice assistant must tag "can fish" with N (noun) or V (verb). The HMM has:

start π
N0.4
V0.6
a(prev → next)NV
N0.40.6
V0.80.2
b(word | tag)canfish
N0.20.5
V0.60.25
  1. Compute the joint probability of all four tag paths and P(can fish).
  2. Which path does Viterbi return? Give its posterior probability.
  3. A colleague says "0.144 means the model is 14% sure of VN". Correct them. What would happen if "fish" had never been seen as a V in training?
Çözüm

(a) Dört yol

  1. P(words, t₁t₂) = π(t₁) × b(t₁, can) × a(t₁ → t₂) × b(t₂, fish)Formülü bir kere yaz. Sıra: başla → kelimeyi üret → geç → kelimeyi üret.
  2. NN = 0.4 × 0.2 × 0.4 × 0.5 = 0.016Soldan sağa çarp: 0.08 → 0.032 → 0.016. Küçük adımlar, hesap makinesi gerekmez.
  3. NV = 0.4 × 0.2 × 0.6 × 0.25 = 0.0120.08 → 0.048 → 0.012.
  4. VN = 0.6 × 0.6 × 0.8 × 0.5 = 0.1440.36 → 0.288 → 0.144.
  5. VV = 0.6 × 0.6 × 0.2 × 0.25 = 0.0180.36 → 0.072 → 0.018.
  6. P(can fish) = 0.016 + 0.012 + 0.144 + 0.018 = 0.19Bütün yolların toplamı (forward da bunu verir).

(b) Viterbi ve posterior

canfish
N0.4 × 0.2 = 0.08max(0.08 × 0.4, 0.36 × 0.8) × 0.5 = 0.144 ← V
V0.6 × 0.6 = 0.36max(0.08 × 0.6, 0.36 × 0.2) × 0.25 = 0.018 ← V
  1. son sütunun en büyüğü: 0.144 (N), geri ok → VViterbi her etiket için en iyi kısmi yolu tutar, sonra geriye takip eder.
  2. best = VN,  posterior = 0.1440.19 = 144190 ≈ 0.76Pay: o yol. Payda: bütün yollar. 190 × 0.75 = 142.5, biraz fazlası → ≈ 0.76.
model "can fish" için VN okumasına %76 inanıyor: "can" fiil (konserve yapmak), "fish" isim → "balığı konserve yap".

(c)

Kâğıda böyle yazarım

0.144 is the joint probability P(can fish, VN): the chance of generating these words and these tags together. It is small because every specific sentence is unlikely. The model's belief in VN for this sentence is the posterior 0.144 / 0.19 ≈ 0.76.

If "fish" was never seen as V, the unsmoothed estimate is b(fish | V) = 0, so every path ending in V (NV and VV) gets probability 0, even when the sentence really is "… they fish". A zero count is not proof that something is impossible, so we use add-one smoothing (and an UNK symbol for unseen words).

Joint ile posterior'ı karıştırma; bu hem şıkta hem yazılıda gelir.
